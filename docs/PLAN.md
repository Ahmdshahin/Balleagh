### نطاق النموذج التجريبي (Demo)
الهدف إن المحافظ **يشوف محافظته** على الشاشة. النموذج مش نظام إنتاج.
1. **تطبيق المواطن** (Flutter، يُعرض على موبايل حقيقي): تسجيل سريع ← تصوير ← تحديد الموقع تلقائياً ← إرسال ← رقم البلاغ.
2. **غرفة العمليات** (ويب): البلاغ يظهر **لحظياً** على الخريطة بصوت تنبيه. نقاط ملونة، وخريطة حرارية، وتلوين الوحدات حسب الأداء، والفلاتر.
3. **حساب رئيس الوحدة:** يستلم البلاغ ← يسنده لموظف ← يقفله بصورة وتقرير.
4. **لوحة المحافظ:** ترتيب الوحدات، والإنذارات، والاتجاه الشهري، وتقرير PDF بضغطة زر.
5. **سجل التدقيق:** عرض الخط الزمني الكامل لبلاغ واحد.

**سيناريو العرض المقترح (7 دقائق):** مواطن في قرية يبلغ عن تعدٍّ على أرض زراعية ← البلاغ يظهر في الغرفة خلال ثوانٍ ← رئيس الوحدة يستلمه ← نقلب على لوحة المحافظ ونشوف وحدة لونها أحمر بسبب التأخير وإنذار ظاهر ← نفتح سجلها الكامل.

## المرحلة 1 — الإصدار الأول (MVP)
**الشرط:** موافقة المحافظ + استلام الحدود الرسمية للوحدات المحلية.
**المدة التقديرية:** 14–16 أسبوع.

| أسابيع | العمل |
|---|---|
| 1–2 | البنية التحتية، الهوية والدخول (OTP، جوجل، مايكروسوفت)، تحميل الحدود الرسمية |
| 3–5 | تطبيق المواطن: تقديم البلاغ، الوسائط، العمل بدون إنترنت، العلامة المائية، الإشعارات |
| 4–6 | محرك التوجيه الجغرافي، كشف التكرار، محرك الأولويات ومدد الحل |
| 6–9 | بوابة الوحدة المحلية (ويب + موبايل)، الحسابات الفرعية، تقرير الحل |
| 8–11 | غرفة العمليات: الخريطة اللحظية، المراجعة والعينات، الإعدادات، الإدخال اليدوي لبلاغات السوشيال |
| 10–12 | المؤشرات، لوحة المحافظ، التقارير، الإنذارات، التصعيد |
| 12–13 | سجل التدقيق، اختبارات الأمان والأداء (1000 بلاغ/يوم × هامش 5 أضعاف) |
| 13–14 | تدريب الغرفة والوحدات، والتشغيل التجريبي على **مركز واحد** |
| 15–16 | تحسينات بناءً على التشغيل التجريبي |

## المرحلة 2 — التعميم
- إضافة باقي المراكز على دفعات، وتدريب كل مركز.
- تفعيل صفحة الشفافية العامة (لو الغرفة قررت).
- مراجعة أوزان المؤشرات ومدد الحل بناءً على بيانات حقيقية.
- إضافة التصنيفات الفرعية بناءً على البلاغات الفعلية.

## المرحلة 3 — التوسع
- تصنيف البلاغ واقتراح الأولوية بالذكاء الاصطناعي (من الصورة والوصف والصوت).
- ربط مديريات الخدمات كجهات تستلم بلاغات محوّلة.
- الرصد الآلي لصفحات وجروبات القرى (بعد المراجعة القانونية).
- الربط الفعلي مع المنظومة الموحدة للشكاوى ومنظومة المتغيرات المكانية.
- كشف التعديات من صور الأقمار الصناعية بمقارنة الصور الزمنية.

## المخاطر
| الخطر | الأثر | المعالجة |
|---|---|---|
| تقديم المنصة كـ«بديل» للمنظومة الموحدة | رفض المشروع | تقديمها كمنظومة محلية **مكمّلة** وجاهزة للربط |
| تأخر استلام الحدود الرسمية | توجيه خاطئ للبلاغات | نطاقات مبدئية من تجميع القرى، ومراجعة يدوية من الغرفة |
| رفض الوحدات للبلاغات لتحسين أرقامها | مؤشرات مضللة | نسبة الرفض كمؤشر مستقل + عينات مراجعة من الغرفة |
| صور قديمة أو مزيفة من المعرض | بلاغات كاذبة | قراءة EXIF + علامة «من المعرض» + صورة الحل من الكاميرا فقط |
| ضعف الإنترنت في القرى | فقدان البلاغات | طابور إرسال بدون إنترنت + ضغط الوسائط |
| مقاومة رؤساء الوحدات | ضعف الاستخدام | تدريب + إخفاء الترتيب الكامل عنهم + دعم من المحافظ |
