# بلّغ — النموذج التجريبي (Demo)

نموذج تفاعلي شغال للعرض على المحافظ. بيغطي الأربع واجهات: المواطن، وغرفة العمليات، ورئيس الوحدة المحلية، والمحافظ.
ده **مش نظام الإنتاج**. البنية المعتمدة للإنتاج موصوفة في [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

## التشغيل
محتاج Node.js 20 أو أحدث. الأوامر بتتشغّل من **جذر المشروع** (`D:\Systems\Blagh_System`)، مش من مجلد demo.

```powershell
npm install
npm start
```

بعدها افتح `http://localhost:4000`. أول مرة بيشتغل، السيرفر بيولّد بيانات تجريبية لوحده.

| الصفحة | الرابط |
|---|---|
| الموقع العام للمواطنين (Landing) | `/` |
| صفحة العرض: روابط كل الواجهات + سيناريو العرض | `/demo.html` |
| الخريطة (Map Viewer) | `/map.html` |
| مركز التقارير | `/reports.html` |
| الإعدادات وإدارة المحتوى (CMS) | `/admin.html` |
| تطبيق المواطن (افتحه على الموبايل) | `/citizen.html` |
| غرفة العمليات | `/ops.html` |
| بوابة الوحدة المحلية | `/unit.html` |
| لوحة المحافظ | `/governor.html` |
| تقرير PDF | `/report.html?days=30` أو `?id=<report>` أو `?unit=<unitId>` |

**إعادة توليد البيانات:** زر في الصفحة الرئيسية، أو `npm run seed` والسيرفر واقف.

## الموبايل
- لازم الموبايل يكون على نفس شبكة الـ Wi-Fi. روابط الشبكة المحلية بتظهر في الصفحة الرئيسية وفي شاشة السيرفر.
- المتصفح بيسمح بالـ GPS على `localhost` أو `HTTPS` بس. على الشبكة المحلية استخدم «موقع تجريبي في الفيوم»، أو اضغط على الخريطة.
- علشان GPS حقيقي على الموبايل، اعمل نفق HTTPS (مثلاً `cloudflared tunnel --url http://localhost:4000`).

## إيه اللي شغال فعلاً
- **التوجيه الجغرافي:** الإحداثيات بتتحول لقرية ووحدة ومركز (Point-in-Polygon). البحيرة والمحمية بيروحوا لغرفة العمليات، وأي نقطة خارج المحافظة بتترفض.
- **كشف التكرار:** نفس التصنيف في حدود 50 م وخلال 14 يوم بيتدمج تحت بلاغ رئيسي واحد، والأولوية بتعلى مع زيادة التكرار.
- **الأولوية ومدد الحل:** الأولوية بتتحدد حسب التصنيف، مع قواعد موسمية. فيه تصعيد تلقائي كل 30 ثانية: رئيس الوحدة ← رئيس المركز ← الغرفة ← المحافظ. وحالة «يحتاج ميزانية» بتوقف العدّاد.
- **قواعد الوحدة:**
  - كل وحدة تشوف نطاقها بس.
  - الرفض لازم يكون بسبب.
  - صورة الحل لازم تكون في حدود 100 م من البلاغ.
  - بيانات المبلّغ مخفية حسب إعداد الغرفة.
  - الوحدة تشوف ترتيبها هي بس.
- **المواطن:**
  - دخول برقم موبايل + OTP. كود العرض **1234**.
  - حد يومي للبلاغات.
  - حتى 5 صور أو فيديو واحد، مع وصف صوتي.
  - علامة مائية على الصور فيها الوقت والإحداثيات.
  - العمل بدون إنترنت (طابور بيتبعت تلقائياً).
  - التقييم، ولو قال «متحلتش» البلاغ بيتفتح تاني ويتصعّد.
- **غرفة العمليات:**
  - خريطة لحظية بصوت تنبيه، ونقاط ملونة حسب الحالة أو الأولوية.
  - خريطة حرارية، وتلوين الوحدات حسب الأداء، وطبقة أقمار صناعية.
  - فلاتر، ومراجعة الحلول والرفض، وإعادة التوجيه.
  - زيارات ميدانية، وإدخال بلاغات السوشيال، والإعدادات.
- **سجل التدقيق:** سجل إضافة فقط، كل صف فيه مربوط بالصف اللي قبله ببصمة SHA-256، وفيه زر للتحقق من سلامة السلسلة.
- **مؤشرات الأداء:** المعادلات اللي في [docs/KPIS.md](../docs/KPIS.md)، ودرجة أداء من 100، وترتيب، وإنذارات، واتجاه أسبوعي.
- **تقارير PDF:** من الطباعة في المتصفح، بلوجو المحافظة.

## حدود النموذج (مقصودة)
- **الجغرافيا:** أسماء القرى حقيقية، لكن أماكنها تقريبية، ونطاقات الوحدات متولّدة (Voronoi + تجميع القرى). هتتبدل من ملف GDB والحدود الرسمية.
- **الدخول:** تجريبي (هيدر `x-user-id`). الإنتاج: OTP حقيقي، و Google/Microsoft OAuth، و JWT.
- **التخزين:** ملف `data/db.json` بدل PostgreSQL + PostGIS، والوسائط في `uploads/` بدل MinIO.
- **الإشعارات:** داخل الصفحة عن طريق Socket.IO بدل FCM/APNs.
- **طبقة الأقمار الصناعية:** Esri للعرض فقط، والإنتاج محتاج ترخيص أو صور رسمية.
- **تطبيق الموبايل:** صفحة ويب للموبايل بدل تطبيق Flutter.
